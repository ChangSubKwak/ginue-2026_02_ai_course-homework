## 실행 방법

1. 이 폴더(또는 압축 해제한 폴더)에서 `index.html`(허브 페이지)을 더블클릭하면 다섯 앱의 안내판이 열립니다.
2. 각 앱 폴더의 `index.html`을 직접 열어도 됩니다. 권장 브라우저: Chrome, Edge(최신 버전).
3. 데이터는 브라우저의 localStorage에만 저장됩니다. 다른 PC로 옮기려면 각 앱의 **JSON 내보내기/가져오기**를 사용하세요.

## 공통 설계

- **기술 스택**: HTML5, CSS3(커스텀 속성 기반 라이트/다크 테마), ES2017 JavaScript. 외부 라이브러리와 빌드 도구를 쓰지 않아 학교 PC·태블릿·전자칠판 어디서나 동작합니다.
- **공통 규약**: 폴더별 완전 독립, `file://` 실행 보장(ES 모듈·fetch 미사용), 브라우저 경고창 대신 인앱 모달·토스트, localStorage 보호 래퍼와 샘플 데이터 내장, 400px 반응형, 접근성(키보드 포커스·aria·reduced-motion), 필요한 앱은 A4 인쇄 스타일.
- **공통 샘플 데이터**: 가상의 ‘가온초등학교 5학년 2반’(담임 이가람, 학생 24명). 실존 인물·학교와 무관합니다.

## 바이브코딩 개발 과정

AI 코딩 도구(Claude Code)와 대화하며 다음 절차로 개발했습니다.

1. **컨셉 제안** — 카테고리마다 현장 교사·학습 효과·기술 완성도 세 관점에서 각각 2개씩 컨셉을 제안받음(총 30개).
2. **심사와 스펙 확정** — 교육적 가치·현장 실용성·구현 가능성·차별성·카테고리 적합성 기준으로 심사해 앱당 1개를 선정하고, 기능 우선순위·화면·데이터 모델·알고리즘·수용 기준이 담긴 구현 스펙을 작성. 다섯 스펙의 중복·학교명·기술 다양성을 한 번 더 정리.
3. **구현** — 공통 구현 규약(`_dev/CONVENTIONS.md`)과 스펙을 바탕으로 앱별로 구현.
4. **검증** — 브라우저 자동화 테스트(Playwright)로 수용 기준을 하나씩 확인하고, 코드 리뷰·UX 리뷰를 별도로 수행해 결함을 수정하는 라운드를 반복.
5. **문서화** — 앱별 개요·설명서와 전체 과제 보고서를 작성하고 제출물을 패키징.

자세한 내용은 `과제제출물/` 폴더의 과제 보고서와 각 앱의 설명서를 참고하세요.
